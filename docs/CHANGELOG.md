## 2026-07-09 (condensed header-audit summary mode)

- **chore(gas): `auditLeadTabHeaders()` was unreadable in practice.** It emits a full 31-column header row per tab, and the Apps Script log viewer truncated the message before `Referral Partners`, `RE Professionals`, `Existing Asset Owners`, `Clients` and `Archive` ever rendered — so the five tabs nobody had ever inspected were exactly the five the audit could not show.
- **feat(gas): `auditLeadTabHeadersSummary()`,** one line per tab (`OK`/`DRIFT`, `rows=`, `cols=actual/expected`, `rewrite=SAFE|NO(has data)`, count of missing name-looked-up headers) plus a drifted-tab footer. ~660 chars for nine tabs against ~6,300 for the full audit. Deliberately prints the *count* of missing key headers, not their names: three long header names across nine tabs is the unbounded growth this mode exists to avoid.
- **feat(gas): `auditLeadTabHeaderDetail(tabName)`,** the drill-down the summary points at. Full per-column diff for one tab, which is now the only way to read a drifted tab's columns without the other eight crowding it out of the log. Throws on an unknown tab name.
- **refactor(gas): `leadTabHeaderAudit(ss, tabName)` extracted** as the single analysis pass, with `renderLeadTabHeaderDetail()` as its shared renderer. All three audit entry points read one verdict object, so the summary cannot report `OK` on a tab the detail calls `DRIFT`. `safeToRewrite` is defined as **drifted AND empty**, never merely empty, so it only ever points at tabs that both need a repair and can take one.
- **verify(gas):** Node harness (`vm`-loaded real `Code.gs`). Differential test asserts `auditLeadTabHeaders()` output is **byte-identical** before and after the refactor. Summary asserted at 662 chars / 13 lines (9.5× smaller, longest line 82 chars), containing all nine tabs by name. Semantics covered against a seeded world: a drifted+empty tab reports `rewrite=SAFE`, a **drifted tab holding data** reports `rewrite=NO(has data)`, a healthy+empty tab reports `safeToRewrite === false` rather than being invited to a pointless rewrite, Referral Partners reads `cols=32/32`, a deleted tab reports `MISSING` instead of crashing, and the detail function names the missing `Lead ID`, excludes other tabs, and throws on an unknown or absent tab name.
- **not claimed:** the harness bounds the log size, it does not reproduce Apps Script's exact truncation threshold. The truncation itself is an observed behavior of the live log viewer.

## 2026-07-09 (Lifetime Leads header repair + cross-tab header audit)

- **feat(gas): `auditLeadTabHeaders()`, read-only.** Dumps every lead tab's data-row count and live header row, diffed per column against `expectedHeadersFor()` and flagging any missing name-looked-up header (`Lead ID`, `Category`, `Heard About`). Nothing in the script had ever read a header row purely to check it, so drift was only ever discovered when an unrelated function tripped over it. This is the first direct way to see the live layout of all nine lead tabs.
- **feat(gas): `repairLifetimeLeadsHeader()`, guarded.** Clears row 1 across the sheet's full width (the drifted header has trailing/blank cells a bare `setValues` would leave behind) and rewrites it from `expectedHeadersFor()`. **Throws rather than running when the tab holds data rows.** `leadRow()` builds a positional 31-value array and `appendRow()` writes it to Lifetime Leads on every submission *without reading the header*, so a wrong header does not imply wrong rows — and rewriting a header over rows written under an older layout moves no cells, it silently relabels every column, after which name-based readers like `eaoBackfillPlan()` copy the wrong cells while appearing healthy. The guard makes that class of corruption unreachable.
- **refactor(gas): `expectedHeadersFor(tabName)` extracted** from the inline ternary in `setupSpreadsheet()`, now the single definition site for a healthy lead-tab header row (`LEAD_HEADERS`; `+ Reports Enabled` on Referral Partners only). Three functions now agree by construction about what a healthy tab looks like.
- **corrected a stale premise:** `Heard About` has been the last element of `LEAD_HEADERS` since it was appended there, so the tempting `LEAD_HEADERS.concat(['Heard About'])` rebuild produces a **32-column header with a duplicate `Heard About`**. Lifetime Leads' correct header is exactly `LEAD_HEADERS` (31 columns). Noted at the `REPORTS_ENABLED_HEADER` definition and in `expectedHeadersFor`'s comment.
- **verify(gas):** Node harness (`vm`-loaded real `Code.gs`) reproducing the reported corrupt Lifetime Leads header (legacy 18-column layout + `Date Submitted`, 12 blanks, `Heard About` stranded at col 31 — the shape `migrateAddHeardAboutColumn()` leaves when it writes into col 31 of an 18-column tab). Confirms: repair yields exactly `LEAD_HEADERS`, one `Heard About`, no blanks, no `Date Submitted`, `Lead ID`/`Referral Code` restored at cols 2/3; the naive `+ 'Heard About'` rebuild duplicates the column; the data-row guard throws and leaves the header untouched; `countMissingEaoCategoryRows()` throws `No "Lead ID" header` before the repair and returns a clean count after; and `auditLeadTabHeaders()` marks a healthy 31-col tab `OK` and Referral Partners `OK` at 32.
- **not done, deliberately:** the eight other lead tabs' live headers were **not** read. `clasp` credentials lack the Sheets scope, so no tab's real header row can be read from this repo — `auditLeadTabHeaders()` must be run from the Apps Script editor to answer that. No other tab was auto-fixed.

## 2026-07-09 (resilient header matching in the EAO backfill)

- **fix(gas): `eaoBackfillPlan` matched header names with an exact, case-sensitive compare against a hardcoded literal, and threw `No "Lead ID" header on Lifetime Leads` against the real Sheet.** Expected names are now **derived** from the schema (`LEAD_ID_HEADER = LEAD_HEADERS[COLS.LEAD_ID]`, likewise `CATEGORY_HEADER` and `HEARD_ABOUT_HEADER`) instead of being a fourth hand-typed copy, and all matching goes through `normalizeHeaderName` (strips `U+200B..U+200D` zero-width; collapses every whitespace run, which in JS `\s` already includes `U+00A0` NBSP and `U+FEFF` BOM; trims; lowercases). `Lead ID` / `lead id` / `Lead  ID` / `Lead<NBSP>ID` / `  LEAD ID ` now all match; `LeadID` and `Referred By Lead ID` correctly still do not. `REPORTS_ENABLED_HEADER` stays a literal (a per-tab extra, genuinely absent from `LEAD_HEADERS`).
- **fix(gas): the same exact-compare existed a second time, in the column projection, and was the more dangerous of the two.** `dstHeaders.map(h => srcHeaders.indexOf(h))` would have written **blank** into any column whose two header cells differed only in case or spacing — including `Lead ID` itself. A blank key is invisible to the `seen` set, so a second run would not recognize those rows and would **insert duplicates**. The function's entire idempotency guarantee rested on an exact string match between two independently hand-edited header rows. Both sites now use a prebuilt normalized `srcIndexByHeader` map (first occurrence wins, `hasOwnProperty`-guarded).
- **fix(gas): a failed lookup is now self-diagnosing.** `headerLookupError` logs and throws the full live header row rendered character by character (`col 2: "LeadID"  len=6  codes=[76,101,97,100,73,68]`), plus the expected name and its normalized form, so a genuine mismatch is readable straight from the execution log with no separate probe function.
- **not changed, deliberately:** `headerIndex(sheet, name)` still matches exactly. Its callers are `reportsEnabledIndex` and `migrateAddHeardAboutColumn`, and in the latter a `-1` drives a **write** (it inserts a column), so loosening the match alters migration behavior on live tabs. Flagged for its own change rather than folded into this one.
- **verify(gas):** new Node harness (`vm`-loaded real `Code.gs`), 46 assertions, all passing — and unlike the prior harness it never builds a header row from `LEAD_HEADERS`, which is exactly why the original bug was invisible to testing. Every source header row is deliberately mangled away from the constant. Covers: 14 drift variants all normalizing to `lead id`; four non-collision cases that must stay distinct; the exact live failure reproduced (`Category` matching while `Lead ID` does not) and then resolving; a full backfill across a source and destination whose headers are mangled **differently from each other**, asserting `Lead ID` and `Email` values land in the right destination columns rather than blank; **idempotency re-verified under mangled headers** (run 2 inserts 0, no duplicates), which is the regression the projection fix prevents; and a genuinely-absent header still throwing, with the char-code dump reaching both the `Error` and `Logger`. The two prior harnesses (registry: 46 assertions; differential old-vs-new: 0 regressions) both still pass unchanged, confirming the derived constants are byte-identical to the literals they replaced.
- **still unconfirmed:** the exact live header cell value was never captured (the `clasp` token has no `spreadsheets` scope), so the *specific* drift is inferred, not observed. The fix covers the whole class; if the live cell turns out to be a genuinely different name (e.g. `LeadID`), the new diagnostic will now say so precisely on the next run.

## 2026-07-08 (schema hardening + per-tab-vs-unified architecture decision)

- **fix(gas): killed the positional-coupling bug the `Heard About` column exposed, and documented the schema decision behind it.** `REPORTS_ENABLED_COL = LEAD_HEADERS.length` inferred a column's position from an array's length, so appending a 31st header silently slid it from index 30→31 while the live **Referral Partners** tab still had `Reports Enabled` at column 31 — `appendRow` would have written the `heardAbout` string into the `Reports Enabled` cell and the `TRUE` seed into unheadered column 32. Replaced with name-based lookup (`headerIndex(sheet, name)` / `reportsEnabledIndex(sheet)`) reading the sheet's real header row; `-1` is handled as a real state (seed write skipped + logged, opt-out read treats it as blank) rather than a guessed index. Any column can now be inserted anywhere in `LEAD_HEADERS` without reasoning about per-tab extras. Added idempotent `migrateAddHeardAboutColumn()` to backfill the nine existing lead tabs that `setupSpreadsheet`'s empty-tab guard skips, *inserting* before `Reports Enabled` (shifting header **and** data together) rather than appending after it. Recorded the **per-tab vs. unified Details-JSON schema** decision in `backend-architecture.md`: per-tab kept because the Contact Groups sync, cold-lead sweep, monthly referral summary, and `onEdit` row-moving all depend on tabs physically existing, and because the Sheet already holds production data; **manual-editing usability is explicitly not a factor either way**; unified JSON becomes the *natural* fit once `crm.` / `api.axispoint.llc` are real work, and should be revisited then, not before; the lightweight middle ground (one `Details JSON` overflow column, the pattern EAO's `Preferences` use already informally follows) is noted. **Requires `clasp push` + `clasp deploy -i`, then one manual run of `migrateAddHeardAboutColumn()`.**
- **verify(gas):** Node harness (`vm`-loaded `Code.gs`, fake `Sheet` with real `insertColumnBefore`/`getRange` semantics, stubbed GAS globals) — 31 assertions, all passing: `reportsEnabledIndex` resolves correctly with `Reports Enabled` last, first, mid-array, whitespace-padded, and absent (`-1`); migration on legacy 30-column tabs lands `Heard About` at column 31 on all nine tabs, shifts `Reports Enabled` to 32 **with its `TRUE`/`FALSE` data intact**, leaves prior columns untouched; a second run mutates nothing and reports `SKIP` for all nine; already-canonical tabs are no-ops; and an explicit regression guard asserts the old `LEAD_HEADERS.length` constant points at the wrong cell on a legacy tab where the new lookup does not.
